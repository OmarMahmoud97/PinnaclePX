# Templates: one content object, tokens only, CSS motion; Aurora is the first

- Status: accepted
- Date: 4 September 2026

## Context

The build guide (`docs/brand-concept-generator-build-guide.md`, steps 6 and 14) asks for ten fixed templates in which only copy, imagery, colour tokens and type change, each declaring its contrast pairs and its copy slots with limits, accepting either logo polarity where it can, and importing nothing but `lib/tokens` and `lib/copy-slots`. Neither module existed, and the ten templates were placeholders. The owner asked for the first, `t01-aurora`, as a seven-section SaaS page that is easy to recolour, reword and re-picture.

## Decision

1. **A template is a function of one content object.** Every word, link and picture Aurora renders arrives through `AuroraContent` (`templates/t01-aurora/copy-slots.ts`); the component holds no copy. The same file declares the character range of every text slot (`AURORA_SLOTS`), the size of every list (`AURORA_COUNTS`), the text-on-background pairs it paints (`AURORA_CONTRAST_PAIRS`) and a pure `auroraViolations` the copy stage can validate against. Images are optional where the layout can draw light instead, and each carries its Pexels credit, which the footer prints.
2. **Colour is the token set, and nothing else.** Templates paint only with the fourteen names in `lib/tokens/types.ts`, as Tailwind classes, with alpha where a tint is wanted (`bg-on-surface/6`), so one set of CSS variables on the preview root recolours the whole page, on a dark surface or a light one. One token was added for this, `on-scrim`, the text over a photograph's scrim; the build guide's scrim solver sets the scrim, never the text. The meaning of `brand-deeper` is fixed by the pairs: the one brand colour that carries `on-brand` or is used as text.
3. **Type is two families on the preview root.** `font-display` and `font-body` are theme utilities that read `--template-font-display` and `--template-font-body` and fall back to Geist, so the site's own pages are untouched and a brand's pair is two properties. The type scale is the site's fluid scale (`text-display` and friends).
4. **Motion is CSS, and the page is complete without it.** Templates cannot import `lib/motion`, which is the point: nothing in a template loads GSAP. Aurora has one page-load moment (the hero's parts rise, the light blooms) and three scroll-driven answers behind `@supports (animation-timeline: scroll())`: the light drifts, the steps' line draws, the photograph settles. The header turns to glass by the same mechanism, which is colour, so it also runs under reduced motion; the entrances become fades there. Browsers without scroll-driven animations see every finished state. The template's one client component is the phone menu.
5. **Each template owns a small stylesheet.** `templates/t01-aurora/aurora.css` holds the keyframes and the data-attribute hooks, scoped under `.aurora`, and is imported by the template's `index.tsx`, so the keyframes ship only with routes that render the template. The Tailwind utilities a template uses still compile into the one site stylesheet, since Tailwind scans every source: Aurora added about 1.3 KB gzipped to it (13,365 B after `next build` on 4 September 2026, budget 14,000). This is the one departure from the standards' single `globals.css`: ten templates' keyframes do not belong in the stylesheet every site page pays for. Tunables that CSS reads sit at the top of the file, as `--motion-*` do in `globals.css`.
6. **The product frame is an illustration built from the brand's words.** The hero shows a window whose title bar, rail, screen title and rows come from the content (the brand name, the feature titles, a hero slot), so it is of this product and never of software in general, and it is `aria-hidden` because the same words are read below. It is clipped at the section's edge, which keeps the first screen short and reads as the product rising from the light.
7. **An example route for design review.** `/examples/aurora` renders the template with an invented brand, Kestrel, whose token set is written by hand in the page the way the tokens stage will derive one. It is `noindex`, unlinked, and outside the sitemap; the examples gallery replaces it. The example content lives with the template (`templates/t01-aurora/example/`) so the template's own test can prove it fits the slots.

## Consequences

- `lib/tokens/types.ts` and `lib/copy-slots/validate.ts` now exist as the first pieces of step 6; `deriveTokens` and the contrast solver join them later and consume `AURORA_CONTRAST_PAIRS`.
- `TemplateMeta` is unchanged. Logo polarity and tone tags join it when the selector needs them; Aurora accepts either polarity because its chrome is plain `surface`.
- Verified on 4 September 2026 at 1440, 768 and 390 px with no horizontal overflow and no console errors, and with axe (WCAG 2.2 AA tags) clean on both the dark example set and a light one.
- The nine remaining templates follow this shape: `copy-slots.ts`, `meta.ts`, `index.tsx`, `sections/`, a scoped stylesheet if they animate, an `example/` folder, and one test that the example fits.
