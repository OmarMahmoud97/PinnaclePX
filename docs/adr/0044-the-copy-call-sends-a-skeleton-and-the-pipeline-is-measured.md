# The copy call sends a skeleton, not a grammar, and the pipeline is measured

## Context

Until this pass no model call had ever been measured: the `model_call` table was empty, the only cost figure was an Aurora-era estimate, and every template after Aurora had been verified against its fallback copy, never against the model. An eval harness (`pnpm eval`, `tests/eval`) now runs the brief, copy and rank calls over twenty frozen invented businesses (`tests/fixtures/eval`) and stops at the rank verdict, so a change can be judged on the same input as the run before it.

The baseline run found the copy stage broken for five of the eight ready templates: the API answered the structured-output call for Monolith, Meridian, Atlas, Harbor and Summit with a permanent 400, "The compiled grammar is too large", and `isPermanentModelError` wrote the fallback at once. 36 of 60 template answers made no call. Only Aurora, Vector and Ember were ever written by the model. Reading the code beside the run found more defects: the copy step kept calling the model after the sweeper had settled the stage; the SDK retried a timed-out request twice inside one call; a company name with a digit broke the rules on every attempt because only the sentence was the allow-list; the picture judge echoed eight-digit Pexels ids and an unjudged picture sorted as accepted; every detail slot of three templates drew on one search of twelve (Ember has eleven detail slots, Summit twelve); Harbor's guide allowed a one-line About heading its validator rejected; the copy prompt told the model to use an owner's sentence it never received, under rules that forbade outright what the judge allowed; and Vector's guide named its menu labels as objects while its schema asked for strings.

## Decision

1. **The copy call sends the shape as a skeleton and checks the answer with the schema.** `copyPrompt` ends with the schema as a JSON value with every string empty and every list one item long (`skeletonOf`, `lib/ai/json.ts`); the call is a plain `messages.create`; the text is read between its first and last brace and parsed with the template's zod schema (`parseJsonAnswer`). A miss of shape is a violation like any other and goes back with the in-call retry. The brief and rank calls keep structured output: their grammars compile. Measured on the baseline's briefs (run `l0-skeleton`): every template answers; a first copy call takes about 2,700 input tokens against 4,309 with the schema.
2. **The owner's words are the company name and the sentence**, for the judge and for the model. `ruleViolationsIn` is judged against both, so a name like A1 Gas and Plumbing is not a number the model invented; the copy prompt opens with the owner's own sentence; and the system prompt's number, claim and superlative rules carry the exception the judge grants, with the word "best" asked for in no sense. Measured on ten fixtures with the same briefs (runs `l6-all-fixes` and `l7-sentence`): the dentist's pages now carry the ten-year crown guarantee the owner wrote, which the earlier copy dropped; copy cost $0.0344 to $0.0355 an answer; first answers fitting 20 of 30 to 16 of 30, seventeen of the new misses one Vector answer that decision 9 addresses; rule hits 7 to 9, the new ones paraphrases of the owner's claims ("Trusted by", "guaranteed") that the substring allow-list does not recognise. Kept for the quality; the fit is within the noise of thirty answers and is re-measured next pass.
3. **A copy step reads the row before it calls, and the SDK does not retry.** `copy-<id>` returns `settled` when the stage is no longer open, so no call runs after the sweep; `CONFIG.ai.maxRetries` is 0, so a stage's timeout is a ceiling and Inngest's cadence is the only retry (ADR 0015).
4. **Rank verdicts come back by position.** The photographs are numbered 1 to n in the prompt and mapped to their ids in code; a verdict naming no position is logged as `rank.unmatched` and dropped; a candidate the judge never mentioned sorts last.
5. **A detail pool is every detail query's pictures, judged once.** The hero still takes the first query that finds any. A failed search lets the next query try, and the last failure stands only when none found anything. `CONFIG.ai.maxTokens.rank` is 2,000 to fit two dozen verdicts. Measured over twenty fresh fixtures: empty slots 63 to 57 and repeated 106 to 75, with Pexels answering 21 of the run's searches with a 500, so the pools were smaller than designed.
6. **Harbor's About heading may be one line**, as its guide says.
7. **The harness, the fixtures and `app/dev/eval` are committed** so the next pass starts from a baseline, and every number in the plan says measured or estimated.
8. **Vector's menu labels are strings**, named `nav.links[]` in the guide and the violations, as the schema shapes them.

## Consequences

- Measured cost after decisions 1 and 3 to 7, run `l6-all-fixes`, twenty fresh fixtures all completing: **$0.135 a submission on average, $0.081 to $0.235**, of which copy $0.116, brief $0.0083 and rank $0.0106. First copy answers fit 36 of 60; 34 of 40 in-call retries fitted; 7 fresh starts; 1 fallback. Before the pass the three templates that answered cost $0.020 to $0.045 an answer and the other five cost nothing because they never answered; after it every template answers at $0.025 (Vector) to $0.086 (Harbor, whose twelve-character value slots the model misses by a character or two).
- The pass's own spend: baseline $1.12, `l0-skeleton` $2.04, `l6-all-fixes` $2.71, `l7-sentence` $1.07, at the prices the pricing page lists on 1 October 2026 (Sonnet 5 $2 and $10, Haiku 4.5 $1 and $5 per million). The account refused every call, including the free token count, three times during the pass: before any pipeline call, after $3.16 of pipeline spend, and after the owner's second top-up until the organisation's balance caught up. A separate project in the same organisation used the rest of the first top-up. The organisation's monthly limit of $30 bounded the last runs.
- Left alone, on evidence: prompt caching (no prefix shared across submissions reaches Sonnet 5's minimum; the in-call retry would pay only above a 28% retry rate); `max_tokens` (ceilings never reached); the brief's second image query (now used by decision 5); the models and thinking setting (a tradeoff for the eval, with the owner).
- Proposed, not applied, because a prompt change goes through the eval and the month's limit is spent: trimming the guides' restated purposes and per-line "characters"; dropping `imageQueries` from the copy prompt; a brief-specific system prompt; the look in the rank prompt and a cap on its reason; Harbor's twelve-character value slots asking for one or two words; Ember's `dishes.items[].note`; trimming over-long prose in code instead of a retry; a slot-only retry; an allow-list that recognises a word's forms. Each is in the plan with its measured evidence.
- The in-call retry carries the whole first answer as text, as before; the `copy.violations` log line is unchanged; the `model_call` row still records no attempt, so retries are read from the harness, not the table.
- `tests/eval/*.eval.ts` run only through `pnpm eval` (its own vitest config); `tests/fixtures/eval/fixtures.json` is frozen; run outputs under `test-results/eval` are ignored by git. `lib/env.ts` exposes `NODE_ENV` for the development-only route.
- The one real end-to-end run on the local stack: attempted twice on 1 October 2026 through the real form on a port 3100 dev server with its own Inngest dev server, a fixture business with the owner's address as the visitor. The send reached the server (POST /start 200) and the Server Action answered "Something went wrong on our side"; no submission row was written and no event reached Inngest. The dev database still lacks migration 0007 (`stage_*_at`, `settled_at`), which the submission insert and every full-row read depend on, so the run waits on `pnpm db:migrate` against that database, the owner's decision, and then one more send.
