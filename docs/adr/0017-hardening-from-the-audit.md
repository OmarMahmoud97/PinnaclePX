# Hardening from the audit: bounded calls, verified uploads, shared imagery, no retry on a permanent model error

- Status: accepted
- Date: 4 September 2026
- Plan: `docs/audit-plan.md`, "Do first"
- Amends: ADR 0009 (decision 6), ADR 0012 (decisions 2 and 3), ADR 0015 (decisions 2 and 3)

## Context

The audit of 4 September 2026 read the whole repository at commit `62d409d` and found five things worth doing first. A stalled Pexels or Blob socket could hold the imagery stage past its budget until Vercel killed the invocation, by which time the sweeper had written a partial page and withheld the email. The upload path was named by a hash the browser computed and nothing on the server checked, and the token route allowed overwrites, so anyone holding a preview link could read the hash from an image URL and put their own bytes under the visitor's logo or photograph, which the pipeline would then re-host on any retry. The imagery stage ran its searches, rankings and re-hosts once per template, so the day a second template is marked ready every submission would search, judge and store the same pictures twice. A model error the API will give again, such as a rejected request or a refused key, was retried every twenty seconds until the deadline. And each preview render read the row twice, parsed the answers three times, and the status poll moved every jsonb column over the wire every three seconds.

## Decision

1. **Every outbound call other than the model's gives up after a time in `CONFIG.timeoutMs`.** A Pexels search after 10 seconds, a download from Pexels or Blob after 30, a store on Blob after 30, with `AbortSignal.timeout` on the fetch and the Blob SDK's `abortSignal` on `put`. The model calls already take `CONFIG.stageBudgetMs`. The Resend SDK's `send` takes no signal, so the email is left to its own function's retries.
2. **An upload is verified where it is used, and never overwritten.** `readUpload` in `lib/blob/read-upload.ts` fetches a visitor's file, computes its SHA-256 and refuses bytes that are not the ones the path names; a URL that is not one of our uploads is refused before anything is fetched. The logo stage and the imagery stage read through it, so a substituted file means the wordmark or an empty slot, never a re-host. The token route sets `allowOverwrite: false`, so a path that is taken stays as it is. Blob answers a second upload to a taken path with an error whose message says the blob already exists (verified against the store on 4 September 2026); the browser then asks `GET /api/upload?pathname=` for the URL of what is there, which is the same file because the path is its hash. The lookup is counted under the same per-address limit as a token.
3. **The imagery stage shares its calls across the templates of a submission.** One Pexels search per query, one ranking per query and purpose, one re-host per picture, with every template waiting on the same promise. Each design takes the best-ranked picture no other design has taken, so the three concepts differ in their photography where the search allows; only once every ranked candidate is taken is a picture shared across designs, and a page never shows the same picture twice. The owner chose distinct pictures over the single best one for every design on 4 September 2026, because three designs with the same photograph read as one template in three colours, which is the opposite of what the page sells. `imageryFor` now takes every chosen template at once.
4. **A permanent model error goes to the fallback at once.** `isPermanentModelError` in `lib/ai/errors.ts` names the SDK's 400, 401, 403, 404 and 422 errors. The brief stage, which is bounded, skips its remaining attempts; a copy call that meets one writes that template's fallback copy and marks the stage `fallback`, so the page is `partial` and the email is withheld, as ADR 0015 decides. Such an error is never the submission's fault: every submission will fall back until the key, the model id or the request is fixed, so it is logged at error level as `stage.permanent` or `copy.permanent`, where Vercel's error filter and a future alert can see it. A timeout, a rate limit or a server error is still retried on the stage cadence until the sweeper settles it.
5. **One row read per preview request.** `readPreview` in `lib/preview/read.ts` wraps the read and the parse of the answers in React's per-request cache, so the page, its metadata and its card share one read; the pipeline keeps reading through `lib/db` directly because it writes between reads. The status poll reads only the stage columns through `readStageRow`.

## Consequences

- `lib/download.ts`, `lib/blob/read-upload.ts`, `lib/ai/errors.ts`, `lib/preview/read.ts` are new; `rehostImage` takes bytes rather than a URL; `runStage`'s bounded option takes `isPermanent`; the upload route answers `GET`.
- A file uploaded before, by this visitor or another, is refused by Blob and found by the lookup, so re-uploading the same logo still works. A file whose bytes do not match its path is logged as `logo.fallback` or `imagery.slot_empty` with the reason.
- The imagery stage's cost and quota use no longer grow with the number of templates chosen, only with the number of distinct queries and pictures.
- Tests: `lib/images/stage.test.ts` counts the searches, rankings and re-hosts across templates and covers the distinct-then-shared rule; `lib/blob/read-upload.test.ts` covers the mismatch and the refused URL; `lib/inngest/stages.test.ts` covers the bounded and permanent paths; `lib/ai/errors.test.ts` the predicate.
