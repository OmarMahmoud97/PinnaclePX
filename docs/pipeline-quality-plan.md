**For:** the owner. **From:** the pipeline pass, 1 October 2026. **Where:** worktree `../PinnaclePX-pipeline`, branch `feat/pipeline-quality` from `origin/main` at 5cae671, eleven commits, unpushed. **Record:** ADR 0044. **Status:** every phase run; eight code changes kept on measured evidence or unit tests; the remaining prompt levers are proposals because the organisation's monthly limit is spent. The phase 1 estimate of 7 cents priced a broken stage's silence.
3. **Eight changes kept, each its own commit with tests:** the skeleton; no copy call after the sweep and no hidden SDK retries; the company name in the allow-list; rank verdicts by position with unjudged pictures last; a detail picture pool from both detail queries; Harbor's one-line heading; the owner's sentence in the copy call with the rules worded as the judge applies them; Vector's menu labels as strings.
4. **What a first answer gets wrong, measured after the fixes:** 36 of 60 first copy answers fit; the in-call retry fixed 34 of 40; 7 needed a fresh start; 1 fell back. Violations were 26 lengths, 18 rules (17 of them the word "best" in a harmless sense), 3 missing sections, 2 counts. Filler words 0, American spellings 0, broken emphasis 0 of 114.
5. **Pictures, measured:** 35% of candidates rejected (faces 54 of 192), every verdict matched a candidate, empty slots 63 to 57 and repeated 106 to 75 after the wider pool, with Pexels answering 21 searches with a 500 during the run.
6. **Credit.** The account refused every call three times during the pass; another project in the same organisation had used the first top-up, and the organisation's $30 monthly limit bounded the last runs. The pass spent $6.94 on the model in four runs.
7. **Decisions for the owner** in section 6.

## 7. The quality rubric and the hand read

Every answer is scored by code; twelve are read by hand; three rendered pages are the owner's. Hand-read criteria score 0, 1 or 2 per template answer.

1. **No invented facts.** Every number, place, product, service, qualification, award, client or guarantee is in the owner's sentence or the company name. Code: `ruleViolationsIn` over the final copy and the brief. Hand: what the rules cannot catch.
2. **British English in the owner's voice.** Code: a list of unambiguous American spellings. Hand: second person to the customer, first person plural for the business, no brochure register.
3. **Specific to the business, not agency filler.** Code: a filler list. Hand: would the owner recognise their trade in the headline, the features and the steps?
4. **Fit on the first answer.** Code only.
5. **Pictures.** Code only, and the owner's read of three rendered pages.
6. **Fallback rate.** Code only.

The twelve hand-read answers are joinery, A1 Gas, the dentist and the vague sentence, all three templates each, from run `l6-all-fixes`. Read against the rubric as written: no invented facts beyond mild reassurance words ("trusted", "reliable", "properly qualified") in four of twelve, scored 1 there and 2 elsewhere; British and in the owner's voice in all twelve; specific in all twelve, the vague sentence producing plain copy that invents nothing. The one systematic loss, the dentist's copy dropping claims the owner wrote, is what commit 9af0cc7 corrects. Screenshots of the twelve from run `l0-skeleton` are under `test-results/eval/l0-skeleton/shots`.

## 9. The real run and how to run the next pass

**The real end-to-end run** was attempted twice on 1 October 2026 through the real form on a port 3100 dev server with its own Inngest dev server (`npx inngest-cli@latest dev -u http://localhost:3100/api/inngest --no-discovery`), the joinery fixture with the owner's address as the visitor. The send reached the server (POST /start 200) and the Server Action answered "Something went wrong on our side"; no submission row was written and no event reached Inngest. The dev database still lacks migration 0007, which the submission insert and every full-row read depend on (a plain `select settled_at from submission` fails there), so the run waits on `pnpm db:migrate` against that database (decision 2) and then one more send; the script is the session's `real-run.mjs` and takes about ten minutes including the five-minute deadline.

`pnpm eval` with `EVAL_RUN=<name>` runs every stage; `EVAL_STAGES=copy EVAL_REUSE_RUN=l6-all-fixes` re-runs copy on the same briefs; `EVAL_STAGES=rank` the same for pictures; `EVAL_FIXTURES=a,b` narrows the set; `EVAL_SUMMARISE=<run>` recomputes a summary; `EVAL_PLAN=1` checks the fixtures without a call. `pnpm dev -p 3100` then `pnpm eval:shots <run> http://localhost:3100 joinery,a1-gas,dentist-claims,vague` takes the twelve pages' screenshots. Spend per full pass, measured: $2.71.
